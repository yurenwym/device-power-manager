# 设备电源管理：C++ 原生 Windows 设计

用户已确认 C++ + Win32、托盘常驻与中文面板、独立设备适配结构。

## 范围
- Windows 10/11 x64；C++17、Win32/GDI、SetupAPI、HID；无第三方运行时。
- 目标设备：HyperX Cloud III Wireless、Ninjutso Sora V2、迈从 Z75S、iLovbee B98。
- 首先验证真实协议，再显示电量。未确认的协议必须显示待适配，不得编造百分比。
- 托盘、按需面板、60 秒默认刷新、手动刷新、低电量提示、自启开关。

## 结构与数据流
`hid` 层枚举接口并按父设备实例识别同型号接收器，封装 RAII 句柄与可取消的异步 I/O。
`adapters` 层通过准确 VID/PID、usage page、报文长度匹配设备；每个适配器负责查询和校验。
后台单工作线程串行读取，不允许重复刷新重叠；主线程通过 PostMessage 接收快照。
`app` 层负责消息循环、托盘、GDI 绘制与原生设置控件。关闭面板销毁窗口；退出等待后台工作完成并删除图标。
设置保存在用户 LocalAppData 的 INI；无后台日志、联网或遥测。开机自启使用用户启动文件夹快捷方式，由用户主动勾选。

## 状态与扩展
百分比为可选值，区分在线、接收器存在但查询无回复、未连接、协议未确认及读取错误。
失败不显示旧电量为当前值；设备身份与适配器分开，两个相同接收器不得合并。
新协议在 adapters 中独立注册；标准 HID Battery Strength 为通用读取入口。
未来蓝牙及其他厂商需单独验证，不承诺所有无线设备自动支持。

## 验证
报文解析单测覆盖短包、错误命令、越界百分比、离线及校验和。
真机执行一次性查询，记录实际响应；检查托盘启停、重复启动、面板关闭、进程退出、句柄增长与空闲 CPU/内存。
